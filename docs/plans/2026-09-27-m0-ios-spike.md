# M0 iOS Implementation Plan

## Direction

Implement the next M0 requirement from the blueprint: one hardcoded iOS request with separate first and warm timings.
Reuse the verified upstream `Scorer` inside an in-process bridge rather than invoking the desktop CLI or rewriting inference.
Generate Xcode projects, resources and native libraries under ignored `.cache/m0/ios/`.

## Owned Paths and Checks

1. `spikes/m0/ios/report.py` and `spikes/m0/tests/test_ios_report.py`: write failing report-validation regressions, then implement numerical and provenance checks.
2. `spikes/m0/ios/prepare.py`: render the existing short Choice fixture using verified inputs and retain the desktop reference.
3. `spikes/m0/ios/Benchmark.*` and `host_main.cpp`: initialize the pinned scorer, reset memory for each sample, compute verdict distributions and capture raw results; verify through a real host run.
4. `spikes/m0/ios/build.py` and `app/`: generate a minimal SwiftUI app and build one SDK at a time with two jobs; verify unsigned iOS arm64 Release compilation.
5. `README.md`: document exact commands and the limits of pretokenized native timings.
6. Run unit tests, the host report reader and scoped Trunk checks; obtain independent read-only code and evidence reviews before publication.

## Device Boundary

Inspect and test the local deliverable before asking to install or launch on the daily iPhone.
An unsigned build and a simulator pass do not establish physical-device latency.
Stop before that device write unless explicit approval arrives.
Do not mark the full M0 milestone complete without a validated physical-device report.
Confirm the observed device run and compare the exported bundled receipt with the local build receipt; the reader's declared device metadata is not proof of execution origin.
